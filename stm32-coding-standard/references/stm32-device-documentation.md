# STM32 型号与官方文档核验

本流程用于把工程中的目标器件和 ST 官方资料建立可审计的对应关系。不要把系列名、开发板名或兼容型号当作精确型号。

## 1. 识别型号

按以下优先级收集证据，并在报告中保留命中文件和原始值：

1. CubeMX `.ioc` 的 `Mcu.Name`、`Mcu.Family` 和 `ProjectManager.*` 字段。
2. 构建配置、编译命令和预处理宏，例如 `STM32F407xx`、`STM32G431xx`；CMSIS 设备头和 `system_stm32*.c` 只能可靠确认到它们声明的粒度。
3. 链接脚本的 Flash/RAM 区域、Cube package 的器件目录、Keil/IAR 工程目标设置和板级配置头。
4. 用户提供的芯片丝印、BOM、原理图或采购料号。只有这些资料通常能确认封装、温度等级和完整订货号，例如 `STM32F407VGT6`。

优先采用能确认最多字段、且与其余证据一致的来源。若 `.ioc`、设备宏和链接脚本不一致，先报告冲突并停止基于该差异作寄存器、存储容量或封装结论。无法确认完整订货号时，记录已确认的系列/子系列及置信边界，例如“确认 STM32G431xx，封装和 Flash 容量未确认”。

## 2. 获取与核验资料

对确认的型号，优先查找用户提供或工程内的 PDF；再检查已安装 STM32Cube package、项目文档目录和 ST 官方产品页。只使用 ST 或用户提供的原始资料作为硬件事实来源，博客和论坛只能用于定位线索。

至少建立以下资料集：

| 资料 | 用途 |
| --- | --- |
| Datasheet (DS) | 精确订货号、封装、供电/电气范围、存储容量、引脚复用摘要、外设实例和时钟上限。 |
| Reference Manual (RM) | 寄存器位定义、复位值、时钟树、外设状态机、DMA/缓存/中断行为。 |
| Errata sheet (ES) | 当前硅修订已知限制、受影响条件、规避措施。 |

从 ST 产品页或 PDF 封面记录文档编号、修订号、发布日期、适用器件和本地路径或官方 URL。Datasheet 不能替代 RM；RM 也不能确认特定封装的引脚或某颗器件的容量。Errata 适用性取决于芯片硅修订；硅修订未知时，不要声称某条 erratum 一定不适用。

网络或 PDF 不可访问时，明确列出缺少的资料和受影响结论。不要编造文档编号、修订号、寄存器位、封装引脚或电气参数，也不要以同系列资料静默替代。

## 3. 阅读与映射

先使用 PDF 的目录、搜索和文本提取定位与任务相关的章节；对表格、时序图、引脚图或文本提取可疑的页面进行渲染检查。需要处理 PDF 时使用可用的 PDF 专用工具和视觉核验，不能只依赖文件名或搜索摘要。

只提取会改变当前设计或审查结论的事实，并保持可定位引用：

- 时钟、供电、温度、Flash/RAM、封装和引脚限制：DS 的表或章节。
- RCC、GPIO/AF、NVIC、DMA、缓存、外设寄存器、复位值和状态迁移：RM 的章节/表。
- 特定版本的工作条件、症状和软件/硬件规避：ES 的条目。

将事实映射到代码中的外设实例、引脚定义、时钟计算、超时、DMA 缓冲区、ISR 和启动顺序。代码审查结论至少写明“文档号/修订版 + 章节或页码 + 代码文件/行号”。对无法在资料中确认的板级连线、电平转换、电源时序和外部晶振参数，保留为待验证假设。

## MCU 档案输出

在首次审查、实现或硬件相关诊断的输出开头提供简短档案：

```text
MCU：STM32xxxx（精确订货号/系列粒度）
识别证据：<项目文件或用户资料>
资料：DSxxxx Rev x；RMxxxx Rev x；ESxxxx Rev x
已核验：<与当前任务相关的 2-4 项约束及引用>
未确认：<封装、硅修订或无法访问资料等>
```

不要为没有硬件相关性的纯 C 逻辑改动强行联网检索文档；但只要结论涉及寄存器、时钟、外设、引脚、电气条件、容量、DMA/缓存或 errata，就必须先完成相应核验。
