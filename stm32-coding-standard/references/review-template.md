# STM32 C 审查输出模板

## 结论

说明工程、目标芯片/工具链、构建基线和本次是否修改代码。构建结果必须包含 errors、warnings、代码/只读数据/RAM 和产物路径。

## 发现

按严重度排序，每条使用以下格式：

```text
[严重度] 标题
位置：path/to/file.c:line
问题：可观察的事实，不写猜测。
影响：运行时、并发、安全、协议或维护后果。
建议：最小可验证修复。
验证：构建、静态分析、单元测试或板级测试。
```

严重度定义：

- P0：可能造成执行器危险动作、内存破坏、死锁/永久阻塞、时钟/总线完全不可用。
- P1：确定的协议错误、数据丢失、竞态、错误处理缺失或异常路径不安全。
- P2：可维护性/可移植性问题，可能在配置变化或长期运行中放大。
- P3：局部风格、注释、命名或重复代码问题，不影响当前行为。

## STM32 额外证据

审查 CAN/UART/I2C/SPI/DMA/中断时，附上：

- 硬件接收 FIFO 与软件队列的所有权和容量；
- ISR 与主循环的读写关系；
- 每个等待循环的超时和恢复动作；
- 标准/扩展帧、RTR、DLC、字节序和 ID 范围；
- 复位、Bus-Off、NACK、DMA 错误和执行器安全状态。
- DMA 缓冲区与 Cache 属性的对应关系，以及缓存维护和屏障调用的位置、顺序（目标带 D-Cache 时必填）；
- `__packed` 结构体和非对齐访问的核验结果，含目标核是否支持非对齐访问；
- 栈余量的测量方法与读数（`_Min_Stack_Size`、map 用量、ISR 嵌套、水位或 MPU 保护区）；
- 看门狗、低功耗状态下的复位/唤醒原因和计数，以及调试暂停时的看门狗行为；
- 编码与换行核验结果（GB2312 合法性、BOM、行尾格式），以及非目标字节未改动的确认。

## 收尾

列出未验证事项，特别是需要示波器、逻辑分析仪、真实传感器、CAN 压力测试或 HIL 才能确认的假设。不要用“编译通过”替代硬件验证。
