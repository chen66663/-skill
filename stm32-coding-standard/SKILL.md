# STM32 C 代码规范

这是一个面向嵌入式交付的审查与实现技能。目标不是机械格式化，而是让代码在资源受限、异步中断、硬件异常和编译器差异下仍然可读、可测、可恢复。

## 使用边界

- 适用于 STM32 C/C++ 中的 C 部分、裸机循环、HAL/LL、CMSIS、标准外设库、板级驱动和应用状态机。
- 用户已有的编码约定、芯片勘误、协议文档和安全要求优先于本技能的推荐项。
- 不修改 ST/CMSIS、启动文件、生成代码或第三方库，除非用户明确要求；对生成文件先说明会被重新生成的风险。
- 不把“符合规范”解释成“必须使用某个库”或“必须改成 C90”。先识别实际编译器、语言标准、优化级别和硬件抽象层。
- 冲突时按以下效力顺序执行：① 用户项目已有规范、芯片勘误、协议和安全要求；② 本文件「强制检查项」；③ `references/local-rules.md` 的「外部共识条目」；④ 同一文件的课件映射（页面要点、章节索引）；⑤ 其余 references 只提供依据和模板，不单独构成规则。按高效力条目执行，并在审查报告中注明偏离理由和所选依据。
- 修改前保留换行和本地命名风格。工程已规定 GB2312 时，所有 `.c`/`.h` 里的全部注释——文件头、函数与数据结构文档块、行内说明、行尾注释——以及新增中文文本一律必须是 GB2312，没有任何例外；发现 UTF-8 注释文件按缺陷报告并逐个修正，不能以“保留原编码”为理由放过。只有工程未规定编码或明确使用 UTF-8 时，才沿用每个文件的原编码，且不得把现有 UTF-8 工程批量转换为 GB2312。

## 工作流程

1. **识别并核验 MCU**：先从工程配置和设备头文件确定精确订货号或最小可确认型号；读取对应的 ST 官方 Datasheet、Reference Manual 和 Errata，形成可追溯的 MCU 档案。具体来源优先级、文档检索和 PDF 核验见 [references/stm32-device-documentation.md](references/stm32-device-documentation.md)。
2. **建立基线**：扫描工程文件、编译器、语言标准、include 路径、链接脚本和构建命令；记录当前错误、警告、镜像大小和 RAM 使用。
3. **划分边界**：区分应用、驱动、启动/CMSIS、生成代码和第三方库；先读公共头文件，再读实现和中断入口。
4. **找高风险问题**：优先检查未定义行为、越界、未初始化、竞态、永久阻塞、错误状态丢失、失联时未关闭执行器和协议字段越界，再处理风格问题。对时钟、GPIO、DMA、缓存、外设实例、复用和电气时序的结论，必须与 MCU 档案中的具体章节或表格相符。
5. **提出最小改动**：保留外部 API 和硬件行为；只有在能减少真实复杂度、重复或风险时才抽象。删除 API 前先确认全工程无调用。
6. **分层验证**：每组修改后先编译；最终要求零错误、零警告，检查 map/hex/axf 产物、编码和换行，并说明未覆盖的板级测试。
7. **交付报告**：按严重程度列出发现、文件/行号、影响、修复和验证结果；报告附上 MCU 型号、识别证据、文档号/修订版和引用页或章节。不能确认的型号、协议或电气假设必须单独标注，不能以相邻型号资料替代。

## 强制检查项

### 编码与注释

- 本技能文件本身使用 UTF-8 保存，便于 Codex 技能发现器读取；不要为了满足工程编码要求把 `SKILL.md`、`agents/openai.yaml` 或 `references/*.md` 转成 GB2312。这 6 个文件已核验为无 BOM 的 UTF-8；用工具读取时出现乱码先怀疑读取端编码设置，不要改动这些文件。
- 若项目已规定 GB2312，则每个 `.c`、`.h` 文件里的所有注释——文件头、函数/数据结构文档块、行内说明、行尾注释——以及新增中文文本一律使用 GB2312：同一工程内不允许存在 UTF-8 中文注释的文件，发现即按缺陷处理并逐个转换。编辑、保存和提交前检查编码，禁止混入其他编码内容；未规定编码时才沿用每个文件的原编码。注释要说明意图、时序、所有权、单位、边界和异常处理，不要逐行翻译代码，也不要为凑比例添加无效注释。
- 编码自检必须同时做三项检查：① 文件开头是否存在 UTF-8 BOM（`EF BB BF`），GB2312 文件不应有 BOM；② 用严格模式按 GB2312 解码，出现解码异常即为非 GB2312 文件；③ 在十六进制视图中查找 `EF BF BD`（U+FFFD）和连续的 `E4`–`E9` 起始三字节序列（UTF-8 中文特征）。注意“按 GB2312 解码再编码字节一致”只是必要条件而非充分条件：GBK 是 GB2312 的超集，UTF-8 中文串在 GBK 下常常能解码成看似正常的乱码（例如 `代码` 的 UTF-8 字节会被解成 `浠ｇ爜`），实际是 GBK 而非 GB2312 的文件也会通过该检查。任何可疑文件都要先确认原编码再决定转换或报告，无法确认时停止批量转换。可执行命令见 [references/check-commands.md](references/check-commands.md)。
- 注释一律使用 `/* ... */` 块注释，禁止使用 `//` 行注释；单行注释也写成 `/* ... */`。禁止 `//` 是本项目和课件的本地规范，与 C 语言标准无关——C99 起 `//` 合法，因此不要用“工程必须降到 C90”来解释这条要求。
- 多行注释每行使用 ` * ` 对齐，例如 `/*` 后换行、每行以空格加星号开头、最后 ` */` 收尾；`/**` 只用于 Doxygen 文档块，不用于普通说明。
- 行尾注释优先对齐到 12 个缩进（12 x 4 空格）；若语句本身超过该位置，则对齐到下一个 4 空格缩进，避免注释挤在代码中间。
- 文件级说明和公共接口文档采用 STM32 标准外设库风格：文件头使用 `/** ... */`，包含 `@file`、`@author`、`@version`、`@date`、`@brief` 和必要的 `@attention`；模块分组使用 `@addtogroup`/`@defgroup`，并以 `@{`、`@}` 成对闭合。示例：

  ```c
  /**
    ******************************************************************************
    * @file    module.c
    * @author  Project Team
    * @version V1.0.0
    * @date    2026-01-01
    * @brief   模块功能概述。
    ******************************************************************************
    * @attention
    *
    * 本文件仅供项目内部使用，修改硬件时序前必须同步更新验证记录。
    ******************************************************************************
    */
  ```

- 需要对外文档的公共接口（判定标准见下文“头文件注释要克制”）采用 Doxygen 块，至少包含 `@brief`、`@param` 和 `@retval`；有前置条件、时序、并发约束或失败恢复时补充 `@note`/`@warning`。参数和返回值说明要写清单位、取值范围、所有权及错误语义，不得只重复变量名。示例：

  ```c
  /**
    * @brief  启动指定通道的 PWM 输出。
    * @param  channel 通道编号，范围为 1 至 4。
    * @param  pulse   比较值，单位为计数器 tick，必须小于周期值。
    * @retval 0       配置成功。
    * @retval -1      参数非法或外设尚未初始化。
    * @note   调用者负责在失联或故障状态下关闭输出。
    */
  int16_t motor_pwm_start(uint8_t channel, uint16_t pulse);
  ```

- 函数实现中的说明注释遵循同一 ST 风格：复杂步骤用独立的 `/* ... */` 块，并可使用 `/* -------- Section -------- */` 分隔硬件时序。只有当用户明确要求“给这段代码全加注释”“逐行补充注释”或同等范围的完整注释时，才把简短说明放在代码右侧并按列对齐，仍必须使用 `/* ... */`，例如：

  ```c
  RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE); /* 先开 PWR 时钟，避免后续寄存器访问无效 */
  PWR->CR |= PWR_CR_PDDS;                             /* 选择待机模式，保持配置顺序 */
  __WFI();                                            /* 进入低功耗，唤醒原因由复位标志判断 */
  ```

- 在上述“完整注释”请求之外，不要默认给每行代码添加注释；只注释确有必要的时序、硬件约束、单位、边界或异常处理。右侧注释超过一行或会显著拉长代码时，改回独立多行块注释。
- 注释内容要写“为什么、何时、谁拥有、失败后怎么办”，不要只写“这里初始化”“这里发送”这类复述代码的注释。
- 头文件注释要克制：只为少数关键接口写文档块——中断或并发上下文、参数所有权与单位、失败语义、安全默认状态；普通读写接口和查询函数保持裸声明，不要给每个声明都配注释块，也不需要为保持格式一致而补注释。
- 头文件顶部只写文件职责和必要的使用约束，不逐条罗列全部函数或参数；对象与函数的详细说明放在对应 `.c` 中。上文关于函数文档块的要求只适用于确实需要文档的接口，不要求覆盖每个声明；文件级注释率门禁是工程整体统计，不是要求每个头文件都达标。
- 新增或修改文件时保持原有换行格式；若无法可靠识别原编码，先报告并停止批量转换，避免乱码和不可逆覆盖。

### 文件、模块和声明

- 每个 `.c` 只定义本模块拥有的对象和函数；头文件只放声明、类型、宏和必要的 `static inline`，不定义普通全局对象或非内联函数。
- 每个头文件有唯一、稳定的 include guard；源文件优先包含对应头文件，之后按标准库、芯片/第三方库、项目模块分组。
- 外部对象只在一个头文件中 `extern` 声明，在一个 `.c` 中定义；模块提供 `Init` 和清晰的读写接口，不让业务层直接改驱动内部状态。
- 全局变量最小化：优先用参数、上下文结构体和模块访问函数传递状态。模块内部状态一律 `static` 限文件作用域，对外只暴露带模块前缀的读写函数；只有确实跨模块共享时才 `extern`，并保持“一个头文件声明、一个 `.c` 定义”。所有全局对象在定义处初始化，并在定义旁注明谁写、谁读、在哪个上下文修改。
- 文件、函数、变量和类型的命名遵循项目现有前缀；新符号必须体现模块归属，避免缩写、通用全局名和宏污染。默认约定：函数和变量用小写 snake_case 并带模块前缀（如 `motor_pwm_start`），类型用 UpperCamelCase（如 `MotorState`），宏和常量用 UPPER_SNAKE_CASE（如 `MOTOR_PWM_MAX`）；工程既有风格不同时（例如整体沿用 ST HAL 的 UpperCamelCase 函数名）沿用现有风格并在报告中注明，不要在同一文件内混用两种风格。
- 命名细则：禁止单字符变量名（`i`/`j`/`k` 等纯循环索引例外）；互斥状态或相反动作用正确的反义词（`Enable`/`Disable`、`Min`/`Max`）；标识符首尾不要加下划线（`_FOO_`），避免与工具链保留名冲突——`__WFI`、`_Min_Stack_Size` 这类由 CMSIS 和启动文件定义，不要复用。

### 控制流和可读性

- `if/else/switch/for/while/do` 的主体一律使用花括号；`switch` 必须有 `default`，有意贯穿的 `case` 要有明确注释。
- `if ... else if` 链必须以 `else` 收尾，除非有明确的穷尽性证明并记录理由；避免悬挂 `else`。
- 不在 `while` 中使用会跳过计数器或状态更新的 `continue`；循环必须有明确进展、上界或超时。每个循环最多保留一个用于结束循环的 `break`。
- 自动变量声明时初始化；指针使用前判空，数组访问前验证长度和索引；禁止返回自动变量地址或把它保存到静态对象。
- 长函数拆成单一职责的静态 helper；参考门禁：圈复杂度不超过 10、嵌套深度不超过 4、函数实现不超过 200 行、重复代码段不超过 25 行。超过门禁时优先拆分决策和硬件动作。
- 圈复杂度按固定口径计算并写进审查报告：复杂度 = 决策点 + 1，决策点统计每个 `if`（`else if` 只是新的 `if`，不要重复计数）、`while`、`for`、`case`、`&&`、`||` 和 `?:`，`else` 本身不计分。超过 10（即 ≥ 11）时必须给出具体拆分方案（抽出判断函数、用查表替代分支、按类型拆 `switch` 分派），不允许只写“复杂度超标”就结束；恰好等于 10 时标记为临界值并说明是否需要提前重构。
- 循环嵌套默认不超过 2 层，出现 3 层要有明确理由并记录，超过 3 层视为缺陷。最内层循环体只做单一动作：不要把协议解析、边界检查、状态机分支和硬件访问一起塞进多重 `for`；遍历二维数据时优先把一维抽成独立函数，或用提前 `break` 把最内层压平，而不是继续加深嵌套。
- 禁止使用 `goto`（MISRA C:2012 Rule 15.1），包括“统一错误清理跳转”这种常见写法。多出口的资源释放改用 `do { } while (0)` 单遍块加 `break`，或把清理动作抽成 `static` 函数在每条返回路径调用；`do { } while (0)` 只承担一次顺序执行，不受上面“每个循环最多一个 `break`”的限制，但不得用它掩盖参数校验失败。
- 注释说明意图、时序、所有权、单位、边界和为什么，避免逐行复述代码；注释率门禁的数值不在本节重复登记，以 [references/local-rules.md](references/local-rules.md) 为准，并按工程整体统计。
- 函数保持可预测：相同输入产生相同输出，不依赖隐藏状态或其它函数的内部实现；接口参数尽量少，模式/开关这类配置参数用独立函数或显式结构体传入，避免一个函数承担多种语义。

### 类型、内存和表达式

- 固定宽度接口使用 `uint8_t/uint16_t/uint32_t/int16_t` 等明确类型；协议、寄存器和长度不要依赖 `int` 或枚举底层大小。
- 有符号/无符号比较、移位、窄化赋值和指针转换必须显式且可证明；移位前确认位宽和符号，避免隐式提升造成的 MISRA/CERT 问题。
- MCU 实时路径默认不使用 `malloc/calloc/realloc/free`；确需动态内存时必须检查失败、定义所有权、释放路径和碎片化策略。
- `const` 用于只读输入、查表和硬件映射；`volatile` 只用于硬件寄存器或 ISR/主循环共享对象，不能用来替代原子性、锁或内存屏障。`volatile` 只约束编译器不优化该访问，不提供顺序和可见性保证；需要跨中断、跨 DMA 或跨缓存保证顺序时，按“缓存、DMA 和内存一致性”一节使用 `__DMB()`/`__DSB()`/`__ISB()`，不要靠堆 `volatile` 解决。
- 只读数据一律 `const`，不能只靠注释声明“本函数不修改”：只读指针参数写 `const T *`；查表、字符串字面量和只读配置结构体加 `const`；返回内部只读数据的接口返回 `const T *`。区分 `const T *p`（数据不可改）、`T *const p`（指针不可改）和 `const T *const p`（两者都不可改）。
- 缓冲区、字符串和协议字段禁用不检查长度的函数：`gets`、`strcpy`、`strcat`、`sprintf`、`scanf` 不得出现在项目代码中。改用 `snprintf`、长度已校验的 `memcpy`，或 `strncpy` 后显式补 `'\0'`；裸机无 `stdio` 时用项目自定义的带长度接口。长度来自外部（协议字段、DLC、配置值）时先钳到目标缓冲区容量再拷贝。
- 每次数组和缓冲区索引都要能证明在界内：下标来自外部时先做上界与符号检查；`sizeof` 只用于同作用域的真实数组，退化为指针后必须改用显式长度参数；环形队列在读写下标取模或回绕前完成容量校验。
- 避免结构体直接作为线协议布局；明确字节序、DLC/长度、缩放、对齐和版本，使用显式序列化函数。
- 结构体默认按自然对齐布局；只有确实需要按字节紧凑时才使用 `__packed`（ARMCC/armclang）或 `__attribute__((packed))`，并在定义旁注明原因。打包结构体成员不得直接解引用：Cortex-M0/M0+ 上非对齐访问会 HardFault，Cortex-M3/M4/M7 上可能产生 UNALIGNED 错误或退化成多次非原子访问。访问打包成员先用 `memcpy` 拷到对齐的局部变量，序列化/反序列化统一走显式字节操作，禁止对打包结构体做指针强转。
- 非对齐访问的来源要逐一确认：把协议缓冲区强转为结构体指针、`uint8_t *` 加偏移后转成 `uint32_t *`、DMA 缓冲区与打包结构体混用、后续改动破坏 `__attribute__((aligned))` 的假设。改动结构体的字段顺序、类型或插入位置后必须重新核对对齐与字节布局。

### 宏、表达式和排版细则

- 函数式宏的实参在每个使用点都要加括号，整个表达式再套一层：`#define APP_AREA(a, b) ((a) * (b))`；多语句宏一律写成 `do { ... } while (0)`，禁止裸 `{ }` 或分号结尾，保证 `if (x) MACRO(); else ...` 能正确展开。
- 调用宏时禁止传入带副作用的实参（`SQUARE(a++)`、`MIN(i++, j)`）；有副作用时先取值到临时变量。宏必须保证实参只求值一次。
- 能用 `static inline` 函数、`enum` 或 `const` 表达的内容不要用宏；宏只用于条件编译、寄存器位掩码、字符串化和拼接（`#`/`##`）。宏体内不得引用参数列表之外的外部符号，避免隐蔽耦合。
- 混合位运算与比较必须显式加括号：`&`、`|`、`^` 的优先级低于 `==`/`!=`，`a & MASK == 0` 是错的，必须写 `(a & MASK) == 0`；`<<`/`>>` 低于 `+`/`-`，同样要加括号。不依赖默认优先级，寄存器操作、移位和赋值表达式一律用括号写明顺序。
- 编译前专项检查易混淆操作符：`=`/`==`、`&`/`&&`、`|`/`||`、`!`/`~`、`<`/`<<`；这类笔误不会产生语法错误。
- 有物理含义的量（电压、周期、超时、阈值、位掩码、量程）不得写成裸数字，必须用带单位的宏、枚举或 `const` 表达，取值范围要与 Datasheet 或需求对应。
- 一行只写一条语句；`if`/`for`/`do`/`while`/`case`/`switch`/`default` 各自独占一行，即使执行体只有一条语句也用花括号。大括号独占一行并与引用它的语句左对齐；工程里已有的紧凑写法沿用现状，新代码不要引入第三种风格。
- 一行不超过 80~100 列；过长表达式在低优先级操作符处换行，操作符放在新行行首，续行相对上一行再缩进。关系紧密的代码放在一起，不使用依赖求值顺序的技巧性写法。
- 对齐只用空格，缩进 4 空格并禁止 TAB。双目操作符两侧加空格；`->`、`.`、`++`/`--`、`!`、`~` 和取地址 `&` 与内容之间不加空格；`if`/`for`/`while`/`switch` 与左括号之间加空格。
- 相对独立的程序块之间、变量声明段之后加空行，避免整段代码粘在一起。
- 注释放在被说明代码的上方或右侧，不放在下方；放上方时与上一段代码用空行隔开，缩进与被说明代码一致；不在表达式中间插入注释；`} /* if */` 这类块结束标记只在跨越较长嵌套、确实难以对照时使用。

### 中断、并发和实时性

- ISR 只做读硬件、清标志、复制必要数据和置通知；不调用 `printf`、阻塞等待、动态分配、复杂协议解析或长循环。
- ISR 与主循环共享数据时定义单生产者/单消费者关系或临界区，说明谁读、谁写、何时发布；多字节对象不能假设单次读写原子。
- 环形队列要明确空/满判定、容量、溢出策略和诊断计数；先复制数据，再发布 head/tail，避免主循环读到半帧。
- 所有硬件等待必须有明确超时、失败返回和恢复动作；禁止无界等待 TXE、TC、CAN mailbox、I2C event、PLL 或外部设备状态。
- 时间比较使用无符号差值 `(now - start) >= period`，兼容 32 位 tick 回绕；周期任务记录实际调度基准，避免漂移和长任务饿死低优先级任务。
- ISR 与主循环都可能调用的函数必须可重入：只用自动变量和参数，不用可变 `static` 状态；必须共享的状态用临界区保护并在函数头注明；禁止局部变量与全局变量同名造成遮蔽。
- 回调函数（`HAL_*_Callback`、`*_IRQHandler`、RTOS hook 和驱动事件回调）在自己的上下文里只做读硬件、清标志、复制数据和置通知。允许：写本模块的 `static volatile` 通知标志、把完整数据写入已定义的单生产者/单消费者环形队列、递增诊断计数。禁止：推进业务状态机、直接改变执行器输出或 PWM 比较值、修改配置量和标定值、调用依赖业务状态的函数。
- 需要推进的状态变更一律先置标志或入队，由主循环统一执行；标志和队列必须在定义处注明谁写、谁读、在哪个上下文修改，并在主循环侧配套读取后清标志、队列空/满判定。确实必须共享的对象用临界区保护，并在函数头注明“在中断上下文调用”。判断标准是区分“写通知”和“改状态”：只置位不解释是允许的，任何对状态的解释都必须在主循环完成。

### 缓存、DMA 和内存一致性

本节适用于带 D-Cache 的型号（Cortex-M7 等）；目标型号无 Cache 时明确说明并跳过，不要用“看起来能跑”代替核验。

- 先确认缓存配置并把结论写进报告：I/D-Cache 是否使能、各 RAM 区域是 Write-Through 还是 Write-Back、哪些区域已通过 MPU 配置为 non-cacheable。结论必须引用 RM 的 Cache/MPU 章节。
- 与 DMA 交互的缓冲区必须二选一并说明理由：① 放在 MPU 配置为 non-cacheable 的区域；② 放在可缓存区域，并在启动传输前对“外设将要读”的内存执行 `SCB_CleanDCache_by_Addr`，在传输完成后对“外设已经写”的内存执行 `SCB_InvalidateDCache_by_Addr`。方向弄反会读到旧数据或丢掉新数据。
- 缓存维护必须按实际字节范围执行，地址和长度按 cache line（Cortex-M7 通常 32 字节）对齐并向上取整；小于一个 cache line 的传输要做整行维护，不能只维护起始地址。
- 缓存维护与 DMA 之间有严格顺序：先写完内存再 Clean，然后才启动 DMA；DMA 完成中断里先 Invalidate 再读数据。该顺序在 Debug 下往往看不出来，必须在代码注释和审查报告里写明。
- 屏障按用途选择：保证访问顺序用 `__DMB()`，等待存储完成用 `__DSB()`，修改指令流或流水线相关状态（自修改代码、MPU/向量表切换）后用 `__ISB()`。屏障不能替代缓存维护，缓存维护也不能替代屏障，两者都要有。
- MPU 区域（基址、大小、权限、属性）必须有单一来源并注明用途；改动链接脚本、堆栈位置或内存布局后，重新核对 MPU 区域与 Cache 属性是否仍然匹配。
- 本节结论必须给出证据：缓存维护调用的位置与顺序、涉及的缓冲区地址和长度、以及对应 RM 章节；只写“已处理 Cache 一致性”不算证据。

### STM32 外设特定要求

- 初始化顺序清楚记录：时钟、GPIO 模式/速度/上下拉、复用映射、外设复位、参数、NVIC/中断、使能和安全默认输出。
- GPIO/定时器/CAN/UART/I2C/SPI/DMA 的引脚、时钟和外设实例只能有一个权威映射源，避免注释、宏和实现三处漂移。
- CAN 必须分别处理标准/扩展帧、数据/RTR、ID 范围、DLC、过滤器、硬件 FIFO、软件队列、mailbox 超时、FIFO 溢出和 Bus-Off；不要把硬件 FIFO 与 SRAM 队列混称。
- UART/I2C/SPI 的读写 API 明确阻塞/非阻塞、长度为 0 的语义、超时单位、NACK/错误标志清理和恢复方式。
- PWM 必须明确计时器时钟、APB 定时器倍频、预分频、周期、比较值范围、通道映射和上电安全脉宽。
- 执行器驱动要有失联、非法命令、初始化失败和总线错误时的安全状态；“最后一次有效命令”不能无限期有效，除非需求明确如此。

### 型号相关专项：浮点、编译器扩展、看门狗和低功耗

- 浮点（Cortex-M4F/M7 等带 FPU 的型号）：确认 FPU 已在启动代码或 `SystemInit` 中使能；浮点结果用容差比较而不是 `==`；ISR 与主循环共享的浮点量用临界区保护或改用整型/定点表示；实时路径不使用 `printf`/`scanf` 的浮点格式化（代码体积和耗时都不可控）；使能 FPU 后重新评估中断栈帧（lazy stacking）和栈余量。
- 编译器扩展：`__weak` 只用于可被覆盖的默认实现，并在注释中写明覆盖点，不能用它隐藏缺失的实现；`__attribute__((section))`、`__attribute__((aligned))`、`__attribute__((packed))` 每个使用点都要注明用途，并确认链接脚本里存在对应段；不用扩展绕过类型检查或压制告警；跨工具链（ARMCC5/armclang/GCC）移植时逐条核对等价写法。
- 看门狗：IWDG/WWDG 的时钟源、超时窗口和喂狗窗口必须留足余量；只从主循环的关键路径喂狗，不在中断里喂狗，以免掩盖主循环卡死；调试暂停时是否停止计数（`DBGMCU`）必须明确并记录；复位原因在上电早期读取并计数，不把看门狗复位和上电复位混为一谈。
- 低功耗：进入前明确关闭哪些时钟、哪些外设保持供电、哪些引脚需要重配置为模拟输入以避免漏电；列出唤醒源和唤醒后的时钟恢复、状态恢复顺序；唤醒后校验外设配置是否仍然有效，必要时重新初始化并重建安全默认输出；进入低功耗前先把执行器置于安全状态。

## STM32 CAN 审查顺序

按以下链路检查一帧报文是否会在每一级丢失或被误用：

```text
CAN 总线
  -> CAN 外设过滤器
  -> 硬件 FIFO0/FIFO1
  -> RX 中断临时结构
  -> SRAM 软件环形队列
  -> 主循环工作副本
  -> IDE/RTR/DLC/ID 校验
  -> 协议状态缓存或状态机
  -> PWM、电源和其他外设
```

逐级确认：硬件 FIFO 是否及时释放；中断是否只复制完整帧；队列是否有空/满和溢出计数；解析前是否验证 DLC；未知 ID、扩展帧和远程帧是否有明确策略；应答发送是否有 mailbox 超时；Bus-Off/FIFO overrun 是否可观测；执行器是否有超时保护。

## 诊断和错误处理

- 公共接口返回明确的成功/失败或项目错误码；不要用“成功但数据无效”隐藏设备离线。
- 所有可能失败的调用都必须检查返回值（MISRA C:2012 Rule 17.7）：HAL/LL 的 `HAL_StatusTypeDef` 返回、外设读写、队列与信号量操作，以及任何返回错误码的库函数，都要显式判断成功、超时和错误分支。忽略返回值只在“失败也无需处理”时有明确理由并写注释，不允许用空的 `if (ret != HAL_OK) { }` 假装检查。
- 同一外设的连续操作要逐步处理失败并计数：不能让错误在后续调用中以更严重的形式出现（例如 I2C 失败后继续读写寄存器、CAN 发送失败后继续推进协议状态、Flash 写失败后继续擦除下一扇区）。
- 错误路径必须释放/复位硬件状态，尤其是 I2C ACK、STOP、CAN mailbox、DMA 通道和执行器电源。
- 计数器至少区分：非法参数、非法帧、未知 ID、DLC 错误、队列溢出、硬件 FIFO 溢出、发送失败和恢复次数。
- 调试日志不能成为实时路径的隐式阻塞点；日志格式包含模块、事件、状态和时间，生产版本可配置关闭或降级。
- 参数合法性检查的责任归属（调用者还是被调函数）必须全组统一，并在头文件或函数头注明；由被调函数承担时要覆盖 NULL、范围、枚举越界和长度/DLC。
- 上电或重载的配置、标定和安全阈值要做一致性检查（长度、版本、CRC/校验和、范围），失败时回退到安全默认值并计数；未校验的外部数据不能直接参与控制。
- Flash/EEPROM/Option bytes 写入、看门狗配置和执行器电源切换属于危险操作：要有写前校验、复位或掉电时的安全状态，以及可回退的备份或二次确认。

## 验证要求

- 编译器警告视为缺陷，除非有局部、可审计的抑制理由；验证 Debug/Release 与实际编译器设置一致。
- 编译告警全开并与项目统一开关（ARMCC5/armclang 的 `-W`、`--diag_warning`、`--strict` 等）；确认无误的告警只用局部 `#pragma diag_suppress` 抑制并注明理由。静态检查（cppcheck、clang-tidy、PC-lint/PC-lint Plus）只对项目代码运行，排除 ST 库、CMSIS 和生成代码。
- 静态分析落地清单：`cppcheck`、`clang-tidy` 和 Clang Static Analyzer（`scan-build`）对项目代码跑通并归档报告。注意三个前提：`cppcheck` 的 MISRA 检查依赖额外的规则文本，`--addon=misra.py` 必须同时提供合法的规则文件，否则只会报规则缺失，不能当作合规证明；`--enable=all` 会引入 `information`/`missingInclude` 噪声，改用 `--enable=warning,style,performance,portability`；嵌入式工程必须先提供 `compile_commands.json` 并配置 `--query-driver` 或等价的目标参数，否则会因找不到头文件而大面积误报。有商业工具时用 PC-lint Plus/FlexeLint 配 MISRA C:2012 规则集，SonarQube 作为长期质量看板。报告要区分“本次新增”和“历史遗留”，禁止用大面积规则抑制把报告刷绿。具体命令见 [references/check-commands.md](references/check-commands.md)。
- 对纯逻辑函数做主机单元测试：边界值、空指针、DLC、ID、字节序、钳位、回绕和状态转移。
- 对外设做板级测试：示波器/逻辑分析仪测时钟与波特率、PWM 周期、UART 波特率、I2C 超时恢复；CAN 测过滤器、FIFO 压力、错误帧、Bus-Off 和恢复。
- 构建完成后记录错误/警告数、代码/只读数据/RAM、产物路径和测试缺口；不把“编译通过”当作硬件正确性的证明。
- 栈与 RAM 余量：记录 `_Min_Stack_Size`、map 文件中的栈用量和 ISR 最大嵌套深度，以及改动前后的差异；加大缓冲或加深调用链后必须重新确认。栈指针在 AAPCS 下要求 8 字节对齐，手写汇编、semihosting 输出和异常入口都要保持该对齐，不能靠“没崩过”来证明。栈溢出检测按可用资源至少选一种并说明未覆盖的部分：MPU 栈保护区、链接脚本栈哨兵值，或栈水位填充（如 `0xC0C0C0C0`）后周期性检查最低水位；栈余量结论必须来自上述证据之一，不能只凭估算。
- 断言只用于检查正常运行时不应发生的情况，Release 下的行为必须明确；断言宏要写成 `do { } while (0)` 以便安全用于 `if/else`，裸机不使用 `printf`/`abort`，改用断点、错误计数或受控复位。调测开关与打印格式全项目统一（至少含模块名与行号），测试代码可通过开关拆卸。
- 改动前建立可回滚备份；改动后确认非目标字节（换行、编码、代码行）未变，避免编辑器和“另存为”改变编码。
